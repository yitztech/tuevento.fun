# Paletas globales

La paleta global solo se cambia en el panel de administración (subdominio `admin`, pestaña Diseño): la paleta inicial Terracota, cuatro propuestas cálidas (Fucsia, Ciruela y Ámbar; Ciruela y Champagne; Mandarina y Frambuesa; Frambuesa y Vainilla) o cuatro frías (Océano y Aguamarina; Bosque y Menta; Índigo y Hielo; Petróleo y Lima). Guardar confirma el cambio global; no hay vista previa. Una respuesta fallida conserva la selección sin guardarla y muestra el error.

La migración `034_site_palette.sql` crea una sola fila, con `terracotta` por defecto, y un `CHECK` que limita los identificadores; la 036 lo amplía y la 037 lo valida. `GET /api/site-palette` es público y no se cachea. La API de la web no tiene ninguna ruta de escritura: el dueño del sitio (`is_owner`) tampoco puede cambiarla. El panel escribe con `PUT /api/palette` de su propio servicio, con sesión del panel, y la función `admin_set_site_palette` (migración 035), porque su rol `admin_ro` no escribe tablas. Valida la entrada con una lista de identificadores; nunca recibe CSS. El contrato del endpoint público está en [openapi/site-palettes.yaml](openapi/site-palettes.yaml); este archivo documenta solo la funcionalidad de paletas, no toda la API.

La tabla de valores e identificadores está en `packages/contracts/src/site-palettes.ts`. La interfaz deriva de ella sus variables CSS; `terracotta` elimina las variables de vista previa para conservar los estilos existentes. El sitio público vuelve a heredar los tokens generales porque `.site-surface` los redefine. Los temas y colores propios de las invitaciones no se modifican. Web y Capacitor cargan la configuración mediante el mismo proveedor; mientras la página está visible se consulta cada 30 segundos. Si la API no responde, la sesión mantiene la última paleta obtenida; en un arranque sin red se muestra la paleta original hasta poder consultar el servidor.

El logo localizado y el símbolo compacto aplican el tratamiento cromático de la paleta activa. El favicon SVG de la pestaña cambia con la misma configuración. Los filtros se definen en `packages/app/src/ui/site/brand-palette.ts`; `node --import tsx scripts/brand-palette-icons.mjs` regenera las nueve variantes a partir del favicon original. El script copia también el logo completo en español a `apps/admin/src/web/brand`: el panel lo tiñe con ese mismo filtro junto a cada paleta, porque su workspace de Angular no puede tomar assets fuera de su raíz. El HTML conserva los favicon PNG/ICO como alternativa antes de cargar la aplicación o en navegadores sin soporte SVG. El icono de Apple para la pantalla de inicio y los iconos instalados de Android/iOS son recursos estáticos gestionados por el sistema operativo y no se actualizan al cambiar la paleta.

Los correos transaccionales consultan la paleta global al enviarse y usan sus colores en línea y el logo PNG del idioma y la paleta correspondiente. Las imágenes se sirven desde el dominio del idioma y se regeneran con `node --import tsx scripts/brand-email-images.mjs`. Si la consulta falla, se usa la última paleta conocida por el proceso (Terracota si todavía no se ha obtenido una) y se registra un aviso. Los gestores de correo pueden bloquear las imágenes externas; el texto alternativo identifica la marca. Los correos de confirmación y las campañas de Listmonk usan plantillas de ese servicio externo y no se actualizan con este mecanismo.

Cada guardado escribe en `admin_audit_log` (`site_palette.update`, el usuario del panel y la paleta), en la misma transacción. La interfaz guarda en `localStorage` (`tuevento.sitePalette`) la última paleta confirmada por el servidor y la aplica antes de pintar: evita el parpadeo a partir de la segunda visita y da la paleta a las apps sin conexión.

## Verificación

- `npm run build -w @tuevento/contracts && npm run build -w @tuevento/client && npm run typecheck`
- `npm run test:unit` verifica la tabla de identificadores, los pares de contraste y la correspondencia con el contrato OpenAPI.
- `npm run test:db` aplica migraciones desde cero y prueba la 034 sobre una base con las migraciones anteriores; la base temporal usa el rol de API.
- `npm run e2e -- --grep @paletas --project=chromium --workers=1` prueba el guardado en el panel, la persistencia, la portada, la protección del endpoint y que el dueño ya no tenga el selector. El escenario usa la base local de pruebas para crear un dueño temporal y restaurar la paleta. Nunca ejecutarlo contra producción.
- `npm run e2e -- --grep @paletas-pantallas` recorre las paletas a 390, 820 y 1440 px: portada, navegación, foco, errores del acceso, panel y modal, con el contraste medido por axe. La paleta se simula en la respuesta de la API: no cambia el estado global.
- `npm run test:security` comprueba que la API de la web ya no tiene endpoint de escritura.

Antes de publicar, ejecutar la batería completa en el entorno de CI y las pruebas de Android/iOS, además de validar en dispositivos físicos. Las capturas de navegador y la emulación no acreditan comportamiento nativo ni funcionamiento sin conexión en un dispositivo.
