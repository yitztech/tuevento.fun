# P08 · Verificación final y cierre

**Objetivo:** probar todo junto, quitar el material del plan y dejar el PR listo para el usuario.

**Antes de empezar:** estás en la rama `feat/pagos-cupones`, P07 terminó y su commit está subido.
Lee las «Reglas para quien implementa» de `docs/plan-nuevo-diseno/README.md`.

## Pasos

1. Ejecuta la verificación completa:

   ```bash
   bash docs/plan-nuevo-diseno/herramientas/verificar.sh
   npm run build
   bash docs/plan-nuevo-diseno/herramientas/pila-ci.sh sube
   bash docs/plan-nuevo-diseno/herramientas/pila-ci.sh api
   bash docs/plan-nuevo-diseno/herramientas/pila-ci.sh todo
   bash docs/plan-nuevo-diseno/herramientas/pila-ci.sh baja
   npm run test:db
   ```

2. Ejecuta las apps. La página de pago también corre dentro de ellas:

   ```bash
   docker compose --profile mobile up -d mobile-tls
   npm run e2e:movil
   ```

3. Mira el CI del PR:

   ```bash
   gh pr checks
   ```

   Todos los checks deben estar en verde.

4. Borra el material del plan. Se conservan el README y `ENSAYO.md`:

   ```bash
   git rm -r docs/plan-nuevo-diseno/tareas docs/plan-nuevo-diseno/fuentes docs/plan-nuevo-diseno/parches docs/plan-nuevo-diseno/traducciones docs/plan-nuevo-diseno/herramientas
   git commit -m "chore: quita el material de Stripe y cupones"
   git push origin feat/pagos-cupones
   ```

5. Escribe en el PR lo que se ejecutó y su resultado, con el resumen de `e2e:movil`:

   ```bash
   gh pr comment --body "<resultado de cada prueba, y lo que no se pudo ejecutar>"
   ```

6. Para y avisa al usuario. **No marques el PR como listo ni lo mezcles.** El usuario debe:

   - Confirmar las decisiones D6 a D10 del README.
   - Marcar el PR como listo y mezclarlo.
   - Seguir «Pendiente, con la cuenta de Stripe» en `docs/PAGOS-PENDIENTES.md`. Hasta entonces no se cobra nada.

## Hecho cuando

- Todo lo anterior pasó y el resultado está en el PR.
- El usuario recibió la lista del paso 6.

## Si falla

- **Un check del CI falla y en local pasa:** copia el error del check y para.
