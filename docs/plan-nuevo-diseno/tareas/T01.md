# T01 · Rama de integración y PR en borrador

**Objetivo:** crear la rama donde vivirá toda la migración. El CI solo corre en pull requests, así que hace
falta un PR en borrador desde el principio.

**Antes de empezar:** el PR #58 tiene que estar mezclado en `main`. Compruébalo:

```bash
gh pr view 58 --json state --jq .state
```

Si no dice `MERGED`, para: los parches se hicieron sobre ese código.

## Pasos

1. Crea la rama con el código de `main` y el material del plan:

   ```bash
   git fetch origin
   git switch -c feat/sitio-nuevo origin/main
   git merge --no-edit origin/docs/plan-nuevo-diseno
   ```

2. Comprueba que el plan está en la rama. Si `docs/plan-nuevo-diseno/README.md` no existe, para.

3. Comprueba que los parches encajan:

   ```bash
   git apply --check docs/plan-nuevo-diseno/parches/T02.patch && echo ENCAJA
   ```

4. Sube la rama con un commit vacío y abre el PR en borrador:

   ```bash
   git commit --allow-empty -m "chore: empieza la migración del sitio público"
   git push -u origin feat/sitio-nuevo
   gh pr create --draft --base main --title "feat(app): diseño nuevo del sitio público" --body "Migración según docs/plan-nuevo-diseno/README.md. Se mezcla al terminar T17."
   ```

## Hecho cuando

- `gh pr view --json isDraft --jq .isDraft` dice `true`.
- El paso 3 escribió `ENCAJA`.

## Si falla

- **`git merge` da conflictos:** ejecuta `git merge --abort`, para y avisa.
- **El paso 3 no encaja:** `main` cambió después de escribir este plan. Para y avisa.
