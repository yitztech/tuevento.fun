# T10 · Se estrena la portada nueva

**Objetivo:** `landing.tsx` pasa a usar las secciones nuevas. Se borran `landing.css` y los textos que ya nadie usa.

**Antes de empezar:** estás en la rama `feat/sitio-nuevo`, la tarea anterior terminó y su commit está subido.
Lee las «Reglas para quien implementa» de `docs/plan-nuevo-diseno/README.md`.

`scripts/test-landing.cjs` cambia una comprobación: el diseño nuevo no tiene vista previa aparte, y la tarjeta
elegida hace ese papel. El resto de la prueba no cambia.

## Pasos

1. Aplica la tarea:

   ```bash
   node docs/plan-nuevo-diseno/herramientas/aplicar.mjs T10
   ```

2. Comprueba:

   ```bash
   bash docs/plan-nuevo-diseno/herramientas/verificar.sh
   ```

3. Levanta la pila de CI y ejecuta toda la suite. Tarda unos 15 minutos:

   ```bash
   bash docs/plan-nuevo-diseno/herramientas/pila-ci.sh sube
   bash docs/plan-nuevo-diseno/herramientas/pila-ci.sh todo
   ```

   Debe terminar con `TODO CORRECTO`.

4. Haz las capturas y vuelve a desarrollo:

   ```bash
   node docs/plan-nuevo-diseno/herramientas/capturas.mjs /
   bash docs/plan-nuevo-diseno/herramientas/pila-ci.sh baja
   ```

   Las tres líneas deben empezar por `bien`.

5. Haz commit y push:

```bash
git add packages/app/src/landing.css \
  packages/app/src/landing.tsx \
  packages/contracts/src/locales/de.json \
  packages/contracts/src/locales/en.json \
  packages/contracts/src/locales/es.json \
  packages/contracts/src/locales/fr.json \
  packages/contracts/src/locales/pt.json \
  scripts/test-landing.cjs \
  tests/e2e/features/sitio.feature \
  tests/e2e/steps/sitio.js
git status --short
git commit -m "feat(app): la portada usa el diseño nuevo"
git push origin feat/sitio-nuevo
```

`git status --short` no debe mostrar en verde nada fuera de esa lista.

## Revisión

Para aquí y pide la revisión. Entrega las capturas de `qa-artifacts/sitio/` y compáralas con las del prototipo.
No sigas con la tarea siguiente hasta que el revisor diga que está bien.

## Hecho cuando

- `pila-ci.sh todo` escribió `TODO CORRECTO`.
- `capturas.mjs` no escribió `MAL`.
- El commit está subido y el revisor dio el visto bueno.

## Si falla

- **`test:landing` falla:** mira `$TMPDIR/test:landing.log`. Si la prueba no encuentra un texto o un rol, para.
- **`e2e` falla en otra característica:** repite solo esa con `pila-ci.sh e2e "<etiqueta>"`. Si vuelve a fallar, para.
- **Resumen con cifras raras:** `pila-ci.sh` borra el resumen antes de empezar; si no hay, el run no arrancó.
