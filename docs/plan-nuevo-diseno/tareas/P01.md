# P01 · Rama de pagos y PR en borrador

**Objetivo:** crear la rama de la Parte B. Es independiente de la migración del sitio y no espera a `feat/sitio-nuevo`.

**Antes de empezar:** lee las «Reglas para quien implementa» de `docs/plan-nuevo-diseno/README.md`.

## Pasos

1. Crea la rama con el código de `main` y copia el material del plan. Se copia, no se mezcla: así funciona también
   si la Parte A ya terminó y quitó su material.

   ```bash
   git fetch origin
   git switch -c feat/pagos-cupones origin/main
   git checkout origin/docs/plan-nuevo-diseno -- docs/plan-nuevo-diseno
   ```

2. Comprueba que los parches encajan:

   ```bash
   git apply --check docs/plan-nuevo-diseno/parches/P02.patch && echo ENCAJA
   ls apps/api/migrations | tail -1
   ```

   La última migración debe ser `029_sync_purged_at.sql`. Si es otra, para: alguien añadió una y hay que renumerar.

3. Sube la rama y abre el PR en borrador:

   ```bash
   git add docs/plan-nuevo-diseno
   git commit -m "chore: empieza el trabajo de Stripe y cupones"
   git push -u origin feat/pagos-cupones
   gh pr create --draft --base main --title "feat: Stripe real y cupones de descuento" --body "Trabajo según docs/plan-nuevo-diseno/README.md, Parte B. Se mezcla al terminar P08."
   ```

## Hecho cuando

- `gh pr view --json isDraft --jq .isDraft` dice `true`.
- El paso 2 escribió `ENCAJA`.

## Si falla

- **El paso 2 no encaja:** `main` cambió después de escribir este plan. Para y avisa.
